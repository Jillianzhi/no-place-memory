# 《不在此处，不在别处》美术素材生成清单与 GPT 任务书

> 本文可以完整发送给负责生成图片的 GPT。请让它严格按批次、逐个生成素材，不要一次把所有物品拼成一张图。

## 给素材生成 GPT 的执行指令

你正在为浏览器 Three.js 互动空间游戏《不在此处，不在别处》制作美术素材。

请遵守以下工作方式：

1. 一次只生成一个场景的一套素材。每生成一套后，标注全部素材编号和文件名，等待我回复“下一个”。
2. 除“场景概念图”外，不要把多个物件拼在同一张图里。
3. 所有可交互物件必须独立生成，不能画进墙面、地面或远景里。
4. 不要在图片里生成中文说明、文件名、水印或 UI 文字。奖状、电子屏、档案卡只生成留白底图，中文由程序后期叠加。
5. 透明物件或独立道具输出透明背景 PNG；材质输出无透视、正面、无阴影的无缝方形贴图。
6. 每次生成前先复述当前素材的编号、用途、画面规格和是否需要透明背景。
7. 不擅自添加人物、鬼脸、血迹、宫廷纹样、赛博霓虹、仙侠元素或现代城市广告。
8. 所有素材属于同一款游戏，光色、材质老化程度和造型语言必须统一。

## 一、背景要不要拆成墙面和地面

**要拆。** 这是一个真正的 Three.js 立体空间，不应把“整间房”做成一张带透视的背景图。

每个场景的环境至少拆为：

- 墙面材质：无缝平铺，不包含门、窗、钟、广播、海报等物件。
- 地面材质：无缝平铺，不包含桌椅、车票、碎片等物件。
- 天花材质：相机能看到天花时使用。
- 窗外或空间深处远景：单独一张平面图，只放不可接触的远处内容。
- 污渍、裂痕、竹影、水光等装饰层：透明 PNG，后期独立叠加。
- 门、窗、家具和交互物件：单独的透明 PNG、建模参考图或 GLB 模型。

### 为什么必须拆开

- 竖屏和横屏由 3D 相机重新构图，不需要各做一套背景。
- 墙面和地面分开后，空间比例、透视和光照才正确。
- 门、窗帘、钟表指针等需要运动，画进背景后无法正确交互。
- 可避免背景里出现一个钟，3D 空间里又出现一个钟的重复问题。

### 不要这样生成

- 不要生成一张包含墙、地面、门、钟、广播和窗户的完整走廊图直接当背景。
- 不要把可交互物件的阴影永久画在背景上。
- 不要为竖屏强行拉长门窗或放大道具。
- 不要生成带明显相机透视的墙面或地面贴图。

## 二、统一视觉规范

### 核心风格

中式梦核，旧时代公共空间与中式园林梦境交叠。空间空无一人，安静、柔软、失真，但不恐怖。视觉像一座可触碰的 3D 微缩舞台或梦境橱窗。

### 必须出现的视觉语言

- 旧学校、老县城客运站、国企家属院、旧放映厅的真实生活痕迹
- 中式圆窗或月洞门作为远景和梦境装饰，不替代真实功能门
- 竹影、水面反光、玉石、瓷器、黑漆木、银色金属枝干
- 少量粉色花瓣、蓝紫柔光、薄雾、浮尘、柔光粒子
- 旧物比例真实，材质有年代感，但不能成为灰色白模

### 色彩建议

- 主墙色：褪色灰绿、旧瓷白、低饱和灰蓝
- 暗部：墨黑、黑漆木、深灰绿
- 梦境光：雾蓝、浅紫、冷白
- 点缀：玉青、瓷白、旧银、少量花瓣粉
- 避免全画面单一紫色，也避免大面积金红、纯黑红和高饱和霓虹

### 统一反向提示词

以下内容用于每一个生成任务：

> 无人物，无人脸，无鬼怪，无血迹，无恐怖跳吓，无赛博朋克霓虹，无现代商业广告，无仙侠人物，无宫廷龙凤金纹，无大面积红金配色，无纯黑背景，无文字乱码，无水印，无 logo，无夸张卡通比例，无廉价白模感，无塑料玩具感，不把多个物件拼在一张素材图中。

## 三、文件规格与交付规则

### 1. 场景概念图

- 格式：PNG
- 尺寸：`1536 × 2048` 或更高，竖屏 `3:4`
- 用途：只用于确认构图、颜色和光线，不直接作为 3D 背景
- 要求：固定视角、完整房间、真实比例、没有 UI、没有人物

### 2. 无缝环境材质

- 格式：PNG
- 尺寸：优先 `4096 × 4096`，最低 `2048 × 2048`
- 要求：正面、无透视、四边可无缝平铺、光照均匀
- 最佳交付：`BaseColor`、`Roughness`、`Normal`、`AO`
- 若只能生成一张图：先交付干净的 `BaseColor`，不要画强烈固定阴影

### 3. 独立平面道具

- 格式：透明背景 PNG
- 尺寸：普通道具 `2048 × 2048`；横向道具 `2048 × 1024`
- 要求：物体完整、不裁切、边缘干净、无环境背景、无落地阴影
- 视角：正面图用于游戏贴图；另做三视图用于后续建模

### 4. 建模参考图

- 格式：PNG
- 尺寸：`2048 × 2048` 或更高
- 一张图可包含同一件物品的正面、侧面、背面、四分之三视图
- 中性浅灰背景，正交视角，不裁切，标明真实尺寸
- 同一物件的活动部件要明确分开，例如钟面和指针、放映机和胶片盘

### 5. 透明遮罩

- 格式：PNG
- 黑白遮罩：白色表示显示或生效，黑色表示透明或不生效
- 用途：雾、雨痕、水光、污渍、竹影、投影噪点

### 6. 命名规则

统一使用小写英文和下划线：

```text
s01_env_school_wall_basecolor.png
s01_prop_radio_front.png
s01_mask_fog_glass.png
s02_prop_ticket_front.png
s03_prop_award_blank.png
s04_prop_archive_bag_closed.png
shared_vfx_petal_01.png
```

## 十二、后续 3D 模型交付规范

图片生成模型通常不能稳定直接交付可用 GLB。更可靠的流程是：先按本文生成概念图、贴图和四视图，再由 Blender 或专业 3D 生成工具制作模型。

### 通用模型规范

- 格式：`.glb` 优先
- 单位：`1 Three.js unit = 1 米`
- 坐标：`Y` 轴向上
- 原点：场景地面中心；独立物件原点放在合理旋转或拖拽中心
- 材质：PBR，避免过多透明层和超高面数
- 移动部件必须拆为独立节点
- 互动节点名称必须完全一致，不能翻译、加空格或改大小写

## 十三、建议生成批次

不要一次生成全部，按以下顺序能最快看到质量提升。

### P0：先做交互核心

1. 场景一：广播、窗帘、雾遮罩、钟面、两个指针、旧木门
2. 场景二：车票、电子屏、雨遮罩、检票箱、客运车门
3. 场景三：声控灯、自行车两状态、奖状、铁门
4. 场景四：放映机、银幕乐园画面、记忆碎片、档案袋开合、档案卡底图

### P1：再做空间材质

1. 四个场景的墙面、地面、天花
2. 窗外与空间深处远景
3. 门窗、座椅、楼梯、桌子、支架等建模参考

### P2：最后做氛围与声音

1. 竹影、水光、花瓣、雾、浮尘、投影噪点
2. UI 图标和档案框
3. 环境声和交互音效

## 十四、每批交付前的自检

- 这件物品是否被错误画进了墙面或地面？
- 可交互物件是否为独立透明 PNG 或独立模型节点？
- 门、窗、钟、桌椅等比例是否符合真实尺寸？
- 场景三是否完全没有儿童乐园？
- 场景四的儿童乐园是否只存在于银幕内部？
- 奖状是否真的是奖状，而不是红纸？
- 钟表是否把钟面、时针、分针拆开？
- 窗帘与雾玻璃是否属于同一个窗框范围？
- 车票、奖状、碎片是否完整、不裁切、便于拖拽？
- 图片里是否没有乱码中文、水印和人物？
- 是否避免了白模、塑料玩具感、赛博霓虹和恐怖废墟感？

通过以上检查后，再进入下一件素材。
